## Change and cause

- The application previously had Turkish text embedded throughout HTML and frontend JavaScript, with no interface-language preference. Public English documentation and screenshots therefore did not match the shipping default UI.
- Added `static/i18n.js`: English is the default for a new profile; `English / Türkçe` is selected in the main header. The choice is stored as `whisperUiLanguage` in the existing protected local storage wrapper and synchronized to the Game Mode overlay.
- Static text, options, placeholders, titles, accessibility labels, and dynamically inserted status/control labels are localized. Switching to Turkish restores the existing Turkish labels; switching back to English updates the current DOM without restarting or losing conversation state.
- Transcript text, translations, AI answers, pronunciations, saved phrases, speaker names, and user-entered text are excluded from interface translation. The product's Turkish-source reply and Turkish-readable pronunciation workflow remains unchanged.
- Added compact responsive styling for the header language selector. Updated the main and overlay HTML templates to load the shared localization layer.
- Updated Chromium/demo fixtures, added `test_ui_language.js` and `npm run test:ui-language`, and regenerated public screenshots/video from the actual Electron renderer under synthetic data so the media reflects the English default.
- Updated README, usage guide, and design contract to explain the new choice.

## Use

- On a fresh installation, open the application: the interface is English.
- In the top header, use **Interface** to choose **Türkçe**. The choice takes effect immediately and is retained for later launches; choose **English** to switch back.
- The Game Mode overlay follows the same stored interface language. The selected conversation/input/translation/reply languages are separate and are not changed by this switch.

## Known limitations and next steps

- The Turkish-friendly pronunciation and fixed Turkish source-language workflow are intentional product behavior, not UI localization bugs.
- External/provider error strings or arbitrary user content are not machine-translated by the interface layer; this avoids changing content semantics.
- Review real-device usage on a clean Windows install before a binary release. Existing local-only Git history credential findings and provider-side key revocation remain separate security follow-up work.
