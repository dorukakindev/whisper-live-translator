# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Whisper Pro is a Windows desktop app for **live, real-time conversation across languages**. It captures system audio (or a microphone), transcribes the other party's speech with faster-whisper, and generates AI reply suggestions. The defining workflow: the user reads the **Turkish phonetic spelling** (`romanized`/`okunuş`) of a suggested reply aloud to speak back in a language they don't know (Japanese, Arabic, Chinese, Russian, Spanish, etc.). Optimize for that read-aloud use — pronunciations must be effortless to read and replies must sound natural to a native speaker.

The codebase and all code comments are in **Turkish**. Match that when editing; keep comment density and idiom consistent with surrounding code.

## Running & building

- **Dev (full app):** `npm start` — Electron (`main.js`) spawns the Flask backend (`buyedektir.py`) on port 5000 and loads the UI. `başlat.bat` is a double-click wrapper for this.
- **Backend only (no Electron):** `python buyedektir.py` (or `calistir.bat`) → serves http://localhost:5000. Override with `HOST` / `PORT` env vars (defaults `127.0.0.1:5000`, local-only). This is the fastest way to iterate on backend/frontend.
- **Build portable exe:** `npm run build` (runs `build.js`, the `electron-packager` Node API with an explicit **allowlist** ignore filter — `main.js`, `main_helpers.js`, `preload.js`, `buyedektir.py`, `requirements.txt`, `package.json`, `templates/`, `assets/`, `static/`, `node_modules/`, nothing else) → `dist/Whisper-Pro-win32-x64/Whisper-Pro.exe`. Rebuild after backend/frontend changes; it does NOT auto-update. Do not revert to a plain `electron-packager .` CLI call or a package.json `build` config block (electron-builder syntax, silently ignored by electron-packager) — a prior version of this script copied the whole project directory unfiltered and shipped real API-key-shaped files (`api.txt`, `OPENAI.txt`, a token file) plus `transcriptions.txt` and `archive/` inside the packaged app; `build.js` also runs a post-build scan for leaked-looking filenames and fails the build if one is found.
- `main.js` prefers a project-local venv (`.venv/`/`venv/`) python, then `python`/`python3`/`py` on PATH; it only kills verified project-owned child processes holding the configured port (a manually started backend is not taken over) and restarts the backend on crash (capped).

`transkribe.py` is a **standalone** tkinter GUI for transcribing audio/video files — unrelated to the live app, shares no code. Run with `python transkribe.py`.

## Testing & validation

There is no test framework. Validate changes with:

- `python -m py_compile buyedektir.py` and `python -m pyflakes buyedektir.py` (keep pyflakes clean).
- `python test_smoke.py` — permanent regression suite (no pytest dependency; exit 0 = pass). Covers the 15-language pronunciation table, the multilingual hallucination filter, the answer-mode contract (parallel calls + `ai_options_partial` streaming + dedup), settings bounds, and the JSON salvage parser. Run after any change to normalization, prompts, or the answer endpoint.
- Frontend JS has no build step. Validate by extracting inline `<script>` blocks from `templates/index.html` and running `node --check` on them.
- Backend route/socket logic can be exercised with Flask's `app.test_client()` and `socketio.test_client(app)` (used previously to verify the parallel-answer and partial-emit paths).
- `test_cevap_onerisi.py` is a manual, opt-in pronunciation-quality eval (not part of `test_smoke.py` — costs real OpenAI credits, needs `OPENAI_API_KEY`). It imports `buyedektir` directly and drives the real `/api/generate_ai_response` route via Flask's test client (no prompt duplication, so it can't drift from production code like an earlier version did), running ~19 golden cases across all supported languages plus two `auto`-mode cases. Each response gets automated checks — non-empty fields, no stray hyphen outside Japanese, no leftover foreign script in `romanized`, and a Turkish-leakage word-list check on `translation` — instead of only eyeballing output. Run after prompt/pronunciation-rule changes: `python test_cevap_onerisi.py`.
- Full smoke test: start the backend (`PORT=509x python buyedektir.py`), confirm `GET /` → 200 and the `/api/*` endpoints respond. Backend startup is slow (~40-50s) due to torch/faster-whisper imports.

## Architecture

**Backend (`buyedektir.py`, ~3000 lines, Flask + SocketIO in `threading` async mode).** One module-global `transcriber` (`WhisperWebTranscriber`) and `mic_recorder` hold all state. Real-time pipeline:

- **Capture thread** (`_capture_audio`) reads native-rate audio, downmixes to mono, resamples to 16 kHz via a cached FIR filter (`_resample_int16`), runs WebRTC VAD to segment on silence, and pushes utterances to `audio_queue` (maxsize 5; drops oldest under load and emits `transcription_lagging`). If VAD never sees silence (continuous speech/music), `MAX_UTTERANCE_S` (15 s) force-flushes the segment — a real production crash (`buyedektir.log`) showed `audio_buffer` growing unbounded to ~20 minutes and faster-whisper failing to allocate a 29 GiB array; this caps it. The forced split doesn't cut at exactly 15 s (would slice mid-word): `_find_quiet_split_index` picks the lowest-energy chunk boundary in the last `SPLIT_SEARCH_S` (1.5 s) window and the tail after that point carries over to the next segment (no audio lost). Falls back to flushing the whole buffer if no window exists.
- **Transcribe thread** (`_transcribe_audio`) pulls from the queue, runs faster-whisper, filters hallucinations (`_is_likely_hallucination`, multilingual), corrects the detected language by script (`_detect_script_lang`), and emits `new_transcription`.
- **Offloaded work:** translation (`translate_executor`, 2 workers) and late speaker diarization (`diarize_executor`, 1 worker and a 1-slot admission semaphore) use separate `ThreadPoolExecutor`s so they never block transcription. A monotonic `_session_id` guards every thread so a stale worker from a previous start/stop can't leak into a new session. Incoming-transcript translation also has a backlog guard: a translation more than `TRANSLATE_MAX_LAG` transcripts behind the latest is skipped (keeps live translations current instead of falling indefinitely behind).
- **Live partial transcription** (`_transcribe_partial`, `_partial_executor`, toggle `partial_enabled` via `/api/partial_toggle`): while speech accumulates, a snapshot of the growing buffer (capped to the last `PARTIAL_SNAPSHOT_S` = 7 s via `_partial_snapshot` — re-transcribing the full buffer every interval was O(n²) and part of the same crash above) is transcribed every `PARTIAL_INTERVAL`s and emitted as `partial_transcription` for a live on-screen preview — before the 1.2 s silence segment finalizes. It NEVER touches the final path (no transcriptions list/file/AI/translation). A `_model_lock` serializes all `current_model.transcribe(...)` calls (partial + final + mic + warmup) since they share one `WhisperModel`; partials skip when a final is queued (`audio_queue` non-empty) so the final is never starved. Each snapshot is tagged with `_utterance_seq` (incremented on every buffer reset/flush); if the sentence finalizes while the partial is still transcribing, the stale result is dropped instead of reappearing as a "ghost" preview after the final. Frontend shows a greyed preview item that `new_transcription` replaces (with a 6 s hide-timer fallback). Push-to-talk (`ptt_buffer`) has its own `MAX_PTT_S` (120 s) cap in case a key-release event is missed (window blur/OS event loss).
- Model load (`load_model`) tries CUDA (float16) then falls back to CPU (int8), scales `cpu_threads` to the machine, and warms the model in a background thread so the first real utterance doesn't pay CUDA/alloc startup. GPU detection allocates a real `torch.zeros(1, device="cuda")` tensor rather than probing for a hardcoded cuBLAS DLL filename — a prior version checked for `cublasLt64_12.dll` specifically, which silently broke (falling back to CPU on a working GPU) once CUDA 13.x renamed it to `cublasLt64_13.dll`. `requirements.txt` installs CPU-only torch by default; see its comments for the CUDA wheel install command.

**AI reply suggestions (`/api/generate_ai_response`).** Modes: `answer` (reply options), `translate`, `translate_dual`. Key design points:

- **Answer mode runs TWO parallel OpenAI calls** (via `_ai_executor`) that split the 4 suggestions by style (2 + 2, see `style_splits`) — latency is dominated by output tokens, so halving per-call output roughly halves wait. Results are merged and deduplicated (`_extract_answer_options` / `_parse_answer_options`); if one call fails the other's options still show. `_salvage_answer_options` recovers truncated JSON.
- **Streaming:** if the UI sends a `request_id`, each parallel call emits its options via the `ai_options_partial` socket event the moment it finishes, so suggestions appear before the HTTP response (which returns the merged, deduped, canonical list).
- **Prompt structure:** static rule blocks (pronunciation guides, tone/quality rules) go FIRST, variable content (context + the message) LAST, to hit OpenAI's automatic prefix caching. Don't reorder casually.
- **Bidirectional conversation memory (`conversation_turns`, deque maxlen 20):** deliberately separate from `context_buffer` (which only ever holds the other party's text and feeds Whisper's `initial_prompt` for transcription language-locking — mixing Turkish into that would break it). `conversation_turns` holds role-labeled `{'role': 'other'|'me', 'text', 'turkish'}` entries from three sources: the main pipeline (role picked from `capture_mode`), Alt-PTT mic dictation (`process_mic_audio`, always `'me'`, `turkish` = the original Turkish before translation), and the user explicitly confirming they said an AI-suggested reply aloud (`POST /api/mark_said`, wired to the "✓ Söyledim" button next to each answer option in `renderAiResult`). Answer-mode prompts render the last 8 turns as `[Ben]: ...` / `[Karşı taraf]: ...` lines with an instruction not to repeat what's already been said — before this, the model had no idea what the user had already said or picked, so suggestions could loop. `/api/clear` resets it alongside `context_buffer`.

**Pronunciation system.** `PRONUNCIATION_GUIDES` holds per-language romanization rules; `_build_pronunciation_guide(lang)` injects ONLY the target language's guide (irrelevant languages degrade quality). `_normalize_turkish_pronunciation(text, lang)` post-processes model output into readable Turkish per language — note Japanese intentionally keeps hyphens (`kore-va`, `suki-des-ka`) while all other languages strip them. `_finalize_pronunciation` is the shared final cleanup.

**Frontend (`templates/index.html` + `static/*.js`, vanilla JS + socket.io).** The main application flow remains inline; Cockpit, reading mode, and quick phrases live in classic global scripts (`static/cockpit.js`, `static/reading-mode.js`, `static/quick-phrases.js`) loaded after the inline block. `renderAiResult` is shared by both the final HTTP response and partial socket events (`partial` flag). Transcript text is kept in a `transcriptionTexts` map keyed by id; the DOM is pruned to `MAX_DOM_ITEMS` and the map is cleaned in lockstep. `window._pendingAiRequests` tracks in-flight answer requests for the streaming path. Always escape interpolated user/AI data with `escapeHtml`/`escapeJsString`.

- **Quick phrases (`⚡ Hızlı Kalıplar`):** `static/quick-phrases.js` holds the `QUICK_PHRASES` object with ~10 ready common phrases per target language (ja/en/es/de/fr/it/pt/ru/ko/zh/ar), each `{tr, t (native, for TTS), o (okunuş)}`, rendered by `renderQuickPhrases()` for the current `aiTargetLang`. The okunuş values are NOT hand-written — they're generated by `_gen_phrases.py` (standalone, imports `buyedektir`) which runs each phrase's phonetic/native form through `_normalize_turkish_pronunciation` so they stay consistent with the rest of the app. To add/edit phrases, edit `_gen_phrases.py`, re-run it, and paste the output into `static/quick-phrases.js`.
- **"Karşı Tarafın Dili" quick-setup (`setOtherPartyLanguage`, `#otherPartyLang` select at the top of settings):** a purely **additive** convenience layer — the individual selectors (the `whisperLang` radios "1. Giriş Dili", `aiTargetLang` "3. Cevap Önerisi Dili") stay fully functional for fine-tuning. "My language" is always Turkish (okunuş is Turkish), so the only variable is the other party's language; picking it sets the Whisper input language (dispatches the radio's existing `change` handler → `/api/whisper_language` + `updateLanguageSettings`) AND the AI answer language (`syncAutoTranslateTargetLang`). Languages the `aiTargetLang` dropdown lacks (ko/pt/fi/sk/az) fall back to `auto` for the answer language (detect → reply in their language). On load the selector only *reflects* current state (no side-effect POSTs).

**Mini overlay (`templates/overlay.html`, served at `/overlay`).** A small, self-contained page — intentionally NOT a stripped-down `index.html` — that connects to the same socket.io backend and shows only the latest transcript + translation + an on-demand AI answer button with large okunuş text. Meant to be loaded in a separate, frameless, always-on-top Electron `BrowserWindow` (see `main.js`: `createOverlayWindow`/`toggleOverlayWindow`, toggled from the tray menu or `Ctrl+Shift+O`) so the user can glance at reply suggestions while focused on a call/game instead of switching to the full window. No settings/favorites/history — that stays exclusive to the main window.

**Global Push-to-Talk (`main.js`, opt-in via tray checkbox, off by default).** The in-app PTT (hold Ctrl/Alt) only works while an Electron window has focus, since it's DOM keydown/keyup. `globalShortcut` has no system-wide "key released" event, so a global hotkey can't reproduce hold-to-talk semantics — `setGlobalPttEnabled`/`toggleGlobalPtt` implement it as a **toggle** instead (press `Ctrl+Shift+Space` once to start, again to stop), calling the same `/api/ptt` endpoint via `net.request` from the main process. This is a genuinely different interaction than the existing hold-based PTT, not a drop-in replacement — surfaced here deliberately since the accelerator or the toggle-vs-hold UX may need revisiting.

## Configuration & gotchas

- Current Python validation has one entry point: use the project `.venv` and run `test_smoke.py`; it also runs the historical suites kept under `tests/archive/`. Run frontend/helper Node tests separately. The manual `test_cevap_onerisi.py` costs API credits; do not run it as a unit test. It sends `buyedektir.APP_TOKEN` in `X-Whisper-Token`.
- Local security: state-changing `/api/*` calls require `X-Whisper-Token` (`WHISPER_APP_TOKEN`). Electron verifies `WHISPER_BACKEND_NONCE`; renderer resynchronizes on `INSTANCE_ID` changes. This is not remote-user authentication: keep `HOST=127.0.0.1`. GET history and socket state are local shared-session data.
- Translation providers are `deepl`, `openai_reseller`, `openai_official` (`openai` is a legacy alias). `OPENAI_BASE_URL`, `OPENAI_MODEL`, `OPENAI_RESPONSE_MODEL` configure the compatible provider; `WHISPER_PYTHON` overrides Python selection; `WHISPER_SKIP_API_VERIFY=1` is for offline tests. OpenAI key saving does not itself verify remote access; the response says `verified: false`. Removing a reseller-specific key may select the shared answer key, which is explicitly reported.
- `/api/glossary` supplies bounded term snapshots. The editor escapes `|` as `\|` and backslash as `\\`. Literal pronunciation overrides apply to exact translated phrases; substring replacement across unrelated native/phonetic alphabets is intentionally not attempted.
- Partial transcription adapts from `PARTIAL_INTERVAL=1.2` to `PARTIAL_MAX_INTERVAL=4.0`; snapshot size is 3.5–7 seconds. `/api/stats` includes rolling latency metrics. Diarization runs after final text publication; a busy slot skips labeling and a late `speaker_identified` event updates the row.
- AI malformed output returns `success: false`, not raw model text disguised as Turkish. Two answer calls contribute at most two options each. Native spelling cleanup and ready Turkish phonetic cleanup are distinct (`phonetic=True`) for ambiguous alphabets.
- `static/whisper-pro-theme.css` owns visual tokens; `static/runtime-safety.js` prevents disabled/full browser storage from crashing initialization and warns when changes are memory-only. `main_helpers.js` and `test_main_helpers.js` cover process ownership and navigation boundaries.

- **Restart the backend after editing `index.html` or `buyedektir.py`.** Flask/Jinja caches the rendered template, so editing `templates/index.html` and just reloading the page serves the OLD HTML — restart the Python process (`başlat.bat` / `npm start`, or `python buyedektir.py`). For the portable `dist/` exe, run `npm run build` (dist is a full copy). This is the #1 source of "my change didn't take effect" confusion.
- **API key:** the AI features read `OPENAI_API_KEY` from the environment/`.env` and call `https://api.openai.com/v1/chat/completions` (default model `gpt-4.1-mini` — chosen via live testing as the best speed/quality non-reasoning mini: ~2.8s/reply, 0% Turkish-leak in the okunuş, no reasoning-token cost; selectable from `allowed_models`). If unset, AI suggestions/translation are disabled (startup logs "OPENAI_API_KEY ... bulunamadı"). The key is verified in a background thread so startup isn't blocked.
- **Secret hygiene:** API keys and tokens belong only in the ignored `.env`; never keep them in notes, transcripts, test fixtures, or other plaintext repository files. `npm run scan` checks the source tree before packaging, but any exposed key must still be revoked and rotated at its provider.
- **Legacy env vars:** `.env` may still carry `MINIMAX_*` keys from an older provider — **the current code ignores them**. Don't wire them back in without intent.
- **`HF_TOKEN`** enables pyannote speaker diarization, which is **lazy-loaded** (only when diarization is turned on, not at startup) to keep launch fast.
- **DeepL** translation is optional (`DeepLTranslator`); when the provider is OpenAI the key lives on the responder. `translate(..., force=True)` bypasses the live-transcription translation toggle for user-initiated (PTT) translations.
- `buyedektir.py` uses **LF line endings** — preserve them when editing on Windows.
- Transcripts append to `transcriptions.txt` (auto-rotates at 5 MB); speaker profiles persist as `speaker_profiles.json` (JSON, not pickle — avoids deserialization risk).
